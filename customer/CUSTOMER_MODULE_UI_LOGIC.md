# منطق واجهة موديول خدمة العملاء

هذه القواعد هي عقد التصميم للموديول ولا يتم كسرها في أي صفحة جديدة:

1. **مركز الخدمة** هو بوابة الموديول فقط، ويجوز أن يكون Landing مختلفًا.
2. كل الصفحات الداخلية تستخدم **هيدر صفحة واحد فقط** من `layout.js`.
3. كل النصوص داخل هيدر الصفحة تكون **بيضاء دائمًا**.
4. بعد الهيدر يأتي شريط الموديول الموحد: **تشغيل / تقارير / إعدادات** ثم زر **لوحة الإدارة**.
5. لا يوجد Sidebar عام داخل الموديول ولا توجد أشرطة تنقل قديمة داخل الصفحات.
6. أدوات الحالة الحقيقية فقط (فحص الاتصال، Provider، Shopify، تحديث البيانات) توضع داخل `mi-customer-runtime-bar` المضغوط؛ لا توجد Hero Cards ثانية.
7. صفحات التشغيل، التقارير والإعدادات تختلف في **محتوى العمل فقط** وليس في هوية الصفحة.
8. الجداول تستخدم نظام الجداول المركزي: حاوية Scroll داخلية، ارتفاع صف مرن، وعدم السماح لأي خلية بتوسيع الصفحة.
9. عمود الطلب/الفاتورة/الكود يعامل كـ LTR داخل الجدول مع Wrap آمن.
10. المصدر الوحيد لعناوين ووصف صفحات الموديول هو `MI_CUSTOMER_PAGE_MODEL` داخل `js/layout.js`.

## تصنيف الصفحات

### تشغيل
- متابعة عملاء نقاط البيع
- سجل الشكاوى
- المراجعة والتحقق المالي
- تشغيل رسائل التقييم
- الإرسال اليدوي للعملاء
- متابعة العملاء غير الراضين

### تقارير
- تقرير أداء خدمة العملاء
- متابعة تقييمات العملاء
- متابعة مكافآت العملاء

### إعدادات
- إعدادات رسائل التقييم
